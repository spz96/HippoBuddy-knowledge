## 一、先建立整体设计认知

HippoBuddy 后端不是 Spring 项目，而是一个轻量、本地优先的 Agent 单体：

```text
WebApplication / DesktopApplication
                ↓
        CoreModule 服务装配
                ↓
    DashboardServer + 虚拟线程
                ↓
         ChatApiHandler
                ↓
      WebAgentOrchestrator
         ↙             ↘
   LlmClient        ToolRegistry
                         ↓
                  工具 + 安全拦截
                ↓
       ConversationService
         ↙              ↘
上下文压缩/Token预算    JSONL会话持久化
```

它的核心设计思路可以概括为：

- 使用 JDK `HttpServer`，不依赖 Spring。
- 使用手写 `ServiceLocator` 完成服务装配。
- 把 Agent 实现成“LLM 决策 → 工具执行 → 结果回填 → 再次调用 LLM”的循环。
- 使用 `LlmClient` 统一适配不同模型供应商。
- 所有工具通过 `ToolRegistry` 注册，并经过 Schema、安全 Blocker、确认机制和文件锁。
- 会话以 `Conversation` 为领域对象，由 `ConversationService` 管理上下文和持久化。
- 通过 SSE 把思考、内容、工具状态和 Token 用量实时推给前端。
- 数据主要保存为 YAML、JSONL、Markdown，不依赖数据库。

完整的项目级分析可以先读：[ARCHITECTURE_REPORT.md](../docs/ARCHITECTURE_REPORT.md:7)。

## 三、第二学习入口：完整聊天主链路

这是后端最核心的源码阅读路线：

### 1. HTTP 接入层

[ChatApiHandler.java](../src/main/java/com/example/agent/web/handler/ChatApiHandler.java:61)

重点看：

- 解析 `sessionId`、用户消息和模式。
- 获取 Session 锁。
- 创建或恢复 `Conversation`。
- 写入用户消息。
- 调用 `orchestrator.execute()`。
- 最后释放锁并关闭 SSE。

真正进入 Agent 的位置在 [ChatApiHandler.java](../src/main/java/com/example/agent/web/handler/ChatApiHandler.java:259)。

### 2. Agent 循环

[WebAgentOrchestrator.java](../src/main/java/com/example/agent/web/orchestrator/WebAgentOrchestrator.java:199)

这是全项目最核心的类。第一遍只看以下节点：

- 第 210 行附近：最多 50 轮的 Agent Loop。
- 第 226 行附近：生成当前推理上下文。
- 第 256 行附近：流式调用 `LlmClient`。
- 第 434 行附近：先持久化 Assistant 决策。
- 第 436 行附近：判断是否存在工具调用。
- 第 459 行附近：执行 Tool Call。
- 第 615 行附近：工具执行、审批、安全拦截和结果回填。

把它理解成一个状态机：

```text
准备上下文
   ↓
调用 LLM
   ↓
组装流式响应
   ↓
保存 Assistant 消息
   ↓
有 Tool Call？ ──否──→ 返回最终回答
   │
   是
   ↓
校验并执行工具
   ↓
保存 ToolResult
   ↓
进入下一轮 LLM
```

配套文档直接读：[Agent Loop 与状态机](../docs/backend-knowledge/03-agent-llm/01-agent-loop-state-machine.md:1)。

## 五、第四学习入口：工具与安全机制

从 [ToolRegistry.java](../src/main/java/com/example/agent/tools/ToolRegistry.java:19) 开始。

重点看三段：

- `register()`：工具注册。
- `toTools()`：把 Java 工具转换成 LLM Function Schema。
- `execute()`：解析参数、安全检查、文件锁、执行和事件发布。

工具注册集中在 [CoreModule.java](../src/main/java/com/example/agent/core/di/CoreModule.java:126)。

最适合的第一个练习是：

1. 仿照 `ReadFileTool` 写一个只读的 `workspace_info` 工具。
2. 实现工具名称、描述、JSON Schema 和 `execute()`。
3. 在 `CoreModule` 注册。
4. 写一个单元测试。
5. 让模型实际调用它。

做完这个练习，你会同时理解 Function Calling、工具注册、Schema、DI 和 Agent Loop。

之后再学习：

- `BlockerChain`
- `SchemaValidationBlocker`
- `BashDangerousCommandBlocker`
- `PathSecurityUtils`
- Human-in-the-loop 工具确认
- `FileLockManager`

路径安全测试是很好的阅读材料：[PathSecurityUtilsTest.java](../src/test/java/com/example/agent/tools/PathSecurityUtilsTest.java:11)。

## 七、建议的实际学习顺序

按这个节奏效率最高：

1. 跑通 Web 后端，发送一次真实消息。
2. 给 `ChatApiHandler.handle()` 打断点。
3. 跟进 `WebAgentOrchestrator.execute()`。
4. 观察一次无工具回答。
5. 观察一次 `read_file` 工具调用。
6. 观察一次需要确认的 `bash` 调用。
7. 查看 `.hippo` 下生成的会话 JSONL。
8. 写一个只读工具并配套测试。
9. 再学习上下文压缩、Memory、SubAgent 和 MCP。

Memory、SubAgent、MCP 都建议放在主链路之后，它们属于扩展能力，不是理解基础 Agent 的前置条件。

## 八、当前环境需要先处理的问题

项目要求 Java 21，但当前 `JAVA_HOME` 指向 JDK 8，导致 Maven 实际使用 Java 8。PowerShell 中先执行：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21'
mvn -version
```

确认输出中的 Java version 是 21，再运行：

```powershell
mvn package -DskipTests
mvn exec:java -Dexec.mainClass="com.example.agent.WebApplication"
```

学习文档本身已经整理成课程形式，可以从 [后端知识库推荐顺序](../docs/backend-knowledge/README.md:7) 开始；但源码实践上，建议优先完成“启动装配 → 聊天主链 → Agent Loop → 工具系统”这四部分。
