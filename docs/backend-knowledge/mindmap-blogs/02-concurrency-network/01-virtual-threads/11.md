# ThreadLocal 成本：底层原理、源码与实现

> 所属专题：[Java 21 虚拟线程](../../../02-concurrency-network/01-virtual-threads.md)  
> 导图路径：边界 → ThreadLocal 成本  
> 类型：线程调度与阻塞卸载节点；编号 11/11

## 1. 学习结论

“ThreadLocal 成本”是线程调度与阻塞卸载节点。掌握标准是能从线程/状态/协议层说明正常路径、竞争路径、超时路径和关闭路径。

## 2. 概念与项目语境

平台线程通常映射到操作系统线程，创建和栈内存成本较高。虚拟线程是 JVM 管理的轻量线程，大量虚拟线程复用少量 carrier 平台线程。

适合：HTTP 调用、文件 I/O、数据库等待、SSE 长连接。慎用：长时间 CPU 密集循环、无限并发外部服务、依赖大量 ThreadLocal 的框架。

## 3. 底层实现原理

虚拟线程身份、Continuation 栈状态与 carrier 执行资源分离；可识别阻塞点卸载，pinning 时 carrier 仍被占用。

分析任何并发实现都要写出：共享状态由谁拥有；哪些操作必须原子；可见性由锁、volatile、原子类还是队列保证；容量耗尽如何传播；取消后谁负责释放实际资源。

## 5. 为什么这样实现

这样保留顺序式代码并提高等待型并发，但业务连接、CPU、内存和配额仍必须单独限流。

若省略该节点，问题通常不会在单线程 happy path 暴露，而会在高并发、慢下游、客户端断开或关闭阶段表现为乱序、泄漏、死锁或假成功。

## 6. 完整代码实现

以下机制代码已通过 Java 21 编译检查：

```java
import java.time.Duration;
import java.util.concurrent.*;

public class BoundedVirtualThreadsDemo {
    static final class Client implements AutoCloseable {
        private final ExecutorService tasks = Executors.newVirtualThreadPerTaskExecutor();
        private final Semaphore permits;
        Client(int maxConcurrentCalls) { permits = new Semaphore(maxConcurrentCalls, true); }

        Future<String> call(int id, Duration deadline) {
            return tasks.submit(() -> {
                if (!permits.tryAcquire(deadline.toMillis(), TimeUnit.MILLISECONDS))
                    throw new TimeoutException("queue deadline exceeded: " + id);
                try {
                    Thread.sleep(100);                 // 模拟可卸载的远程 I/O
                    return "ok-" + id;
                } finally {
                    permits.release();
                }
            });
        }
        public void close() throws InterruptedException {
            tasks.shutdown();
            if (!tasks.awaitTermination(2, TimeUnit.SECONDS)) tasks.shutdownNow();
        }
    }

    public static void main(String[] args) throws Exception {
        try (Client client = new Client(10)) {
            var futures = new java.util.ArrayList<Future<String>>();
            for (int i = 0; i < 100; i++) futures.add(client.call(i, Duration.ofSeconds(2)));
            for (Future<String> f : futures) System.out.println(f.get());
        }
    }
}
```

把与“ThreadLocal 成本”有关的保护删除或移位，再用 latch/barrier、短 deadline 或强制异常稳定复现失败，不要只用 sleep 猜测时序。

## 7. 疑难点与失败推演

- 线程安全容器不保证跨多步业务不变量；
- timeout 只停止等待，不自动取消底层 I/O；
- 虚拟线程降低线程成本，不提供下游背压；
- 成功事件、状态提交和资源释放的顺序必须能经受中途崩溃。
