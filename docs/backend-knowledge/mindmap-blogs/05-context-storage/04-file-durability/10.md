# truncated tail：底层原理、源码与实现

> 所属专题：[批量刷盘、幂等、原子写与崩溃恢复](../../../05-context-storage/04-file-durability.md)  
> 导图路径：Recovery → truncated tail  
> 类型：Token 编码与预算节点；编号 10/12

## 1. 学习结论

“truncated tail”是Token 编码与预算节点。掌握标准是能区分真相状态、派生索引/缓存、持久化确认点与失败恢复点。

## 2. 概念与项目语境

`Writer.flush()` 只把 Java 用户态缓冲推给操作系统，`FileChannel.force(true)` 才请求把文件内容和元数据推进稳定存储；即使 force 返回，硬件/文件系统仍有各自保证。`Files.move(ATOMIC_MOVE)` 只保证命名切换不暴露半文件，不自动保证新文件数据在断电后存在。

覆写类数据的可靠顺序通常是：同目录写 temp → channel.force(true) → atomic move → 尽可能同步目录元数据。追加日志则需要定义 ack：是入内存队列、write、flush 还是 force 后才对调用方成功。批量 force 提升吞吐，但扩大最多丢失窗口，文档和指标必须说清楚。

## 3. 底层实现原理

文本经模型特定 tokenizer 编码；ContextWindow 计算派生占用，TokenBudget 按 crossing 触发 warning/compact/block，并预留输出与安全余量。

源码阅读依次确认：数据单位和稳定身份；写入/更新顺序；内存可见与磁盘 durable 的边界；索引缓存失效；重放、压缩或迁移后的不变量。

## 5. 为什么这样实现

这样在请求前阻止上下文超限，同时用服务端 Usage 校准估算而不混淆预测与账单。

更简单的实现常混淆 estimator 与 Usage、flush 与 force、缓存与真相源，导致边界时超限、崩溃丢失或查询读到陈旧数据。

## 6. 完整代码实现

以下机制实现已通过 Java 21 编译检查：

```java
import java.io.IOException;
import java.nio.ByteBuffer;
import java.nio.channels.FileChannel;
import java.nio.file.*;

public final class DurableReplace {
    static void write(Path target, byte[] bytes) throws IOException {
        Path absolute = target.toAbsolutePath().normalize();
        Files.createDirectories(absolute.getParent());
        Path temp = Files.createTempFile(absolute.getParent(), ".durable-", ".tmp");
        boolean moved = false;
        try (FileChannel channel = FileChannel.open(temp, StandardOpenOption.WRITE,
                StandardOpenOption.TRUNCATE_EXISTING)) {
            ByteBuffer buffer = ByteBuffer.wrap(bytes);
            while (buffer.hasRemaining()) channel.write(buffer); // write 允许 partial
            channel.force(true);
        }
        try {
            Files.move(temp, absolute, StandardCopyOption.ATOMIC_MOVE,
                    StandardCopyOption.REPLACE_EXISTING);
            moved = true;
        } catch (AtomicMoveNotSupportedException e) {
            throw new IOException("atomic replace unsupported", e);
        } finally {
            if (!moved) Files.deleteIfExists(temp);
        }
    }
}
```

围绕“truncated tail”制造越级阈值、partial write、重复事件、外部编辑、索引损坏或检索 miss，验证恢复策略。

## 7. 疑难点与失败推演

- 字符数、估算 Token、服务端 Usage 和费用不是同一概念；
- JSONL 可追加不等于事务，atomic move 也不自动等于断电耐久；
- 摘要必须维持消息协议而不只是变短；
- index/cache 必须可从真相源重建，不能反过来成为唯一数据。
